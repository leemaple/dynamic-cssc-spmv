## Fixed factors and input algorithm

`config/r1-native-supplement.json` fixes all numeric settings. Three public
date-coded workload seed scalars (2026100501/02/03) are selected prospectively;
they have not entered a generator. They are unrelated to cryptographic or mask
randomness, which continue using their existing secure sources. Do not substitute
a seed after any formal outcome. Tests and calibration use disjoint domains.

The Cartesian group order is rows (256,1024), distribution
(concentrated,dispersed), queries per window (1,8), then the three seeds. This
gives group IDs 0..23. Each group runs three fresh technical repetitions and
three strategies, 216 complete executions and 7776 queries in all. No warm-up
is discarded. Each execution has a fresh process, state, keypair and ledger.
Within each group the three strategies and repetitions run serially on the
same runner. Order is `balanced_strategy_order(group,repetition)`, using each
of the six permutations exactly twelve times across the 72 triples.

The tested logical-only generator `r1_workloads.py` is reused unchanged in its
scientific algorithm. Initial/updates/query RNGs have separate SHA-256-derived
domains and use the fixed Python version. Every row begins with eight distinct
columns and nonzero values in [-7,7]. Each of eight windows modifies/deletes/
inserts 8/8/16 coordinates at the small size or 32/32/64 at the large size.
The concentrated candidate domain is the first 16/64 rows; dispersed uses all
rows. Only current logical legality influences sampling. No duplicate touched
coordinate, cancellation, strategy-aware rejection or overflow resampling is
allowed. Updates are applied as one batch, followed by one publication and h
queries. Low h uses x[w,1], high h uses x[w,1..8], so every window is paired.

## Measurement boundary

Reuse the persistent adapter verified in engineering. Its legacy native
`engineering-v1` command/receipt names are wire-format identifiers, not an
evidence classification. Only the prospective formal wrapper and its tagged
provider run can produce this supplement's candidate results; engineering
receipts can never be admitted by renaming them.

The outer measured interval starts before workload validation and state/context
initialization and ends after native close, process exit and resource-sampler
shutdown. It excludes workload generation, binary build, environment capture
and terminal-summary preparation/serialization. It includes Python state
maintenance, compilation, repeated validation, masking/ledger, private local
IPC, actual permitted message serialization/deserialization, encryption,
homomorphic evaluation, decryption, B reconstruction, correctness oracles and
event logging. Never construct an end-to-end time by adding weighted kernels.

Report initial setup/publication separately and the observed post-initial
lifecycle difference. Query `reconstruction_ns` is required B work;
`oracle_ns` is verification only. Do not subtract either from the primary
whole-harness comparison. Other mixed timers remain labeled mixed. All
recurring validation and adapter overhead applies to every strategy.

Count serialized bytes by actual direction A->Cloud, A->B, B->Cloud, Cloud->B,
distinguishing initial keys, publication and query payloads. Metadata and
rotation-key augmentation use full snapshots, not hypothetical patches. Decoded
metadata/public keys must be consumed by the receiver checks/computation. Private
combined test inputs and IPC are not protocol messages. No network latency is
measured. Record matrix old/new/unique transient serialized inventory, keys,
private ledger bytes, base and delta live/tombstone/unused terminal lanes.
RSS high-water marks are checkpoint observations, not a guaranteed whole-lifetime
or simultaneous peak; Linux 100-ms RSS/disk samples are non-atomic estimates.

The producer checks every returned slot, global logical SpMV output, query
binding consumption, native counts and cache preservation. Full private inputs,
mask samples, secret keys and ledgers are not public artifacts. Independent
reconstruction regenerates logical data and checks every recorded global output
and coverage/identity/phase invariant; it does not independently decrypt stored
ciphertexts, re-prove slot correctness or reproduce native timing.

## Resource fit and failures

Use standard ubuntu-24.04 hosted runners, fixed Python 3.12.13, pinned OpenFHE
commit, Release build, at most two concurrent jobs and one OpenMP/OpenBLAS
thread for measurements. Build parallelism is two. Record actual CPU/OS/image,
compiler, dependencies, source and native binary digest. Never spend on a larger
runner. Pair members share a runner; cross-group hardware need not be identical
and will be reported, not silently pooled as identical hardware.

Each complete measured trace has a 300-second alarm; its parent allows at most
330 seconds for the child including input generation/startup/exit. Per-process RLIMIT_AS is 4 GiB;
per-file RLIMIT_FSIZE is 256 MiB, inherited by its native child. These are NOT
enforced combined-RSS or aggregate-disk bounds. Fresh child Python processes
isolate each trace's limits/high-water marks. Jobs have a 55-minute ceiling,
including build/setup/collection. The 24-job worst-case reservation is 22
runner-hours, inside the 40-hour formal allocation. One independent collection/
reconstruction job is capped at 110 minutes, inside its two-hour allocation.
Cold pinned builds have been observed at 118 and 153 seconds in the engineering
runs, so the allowance does not assume cross-branch cache access. These are
calibration observations, not a guarantee of hosted-runner setup time.
Engineering remains bounded at six aggregate runner-hours/two focused days;
the campaign total ceiling remains 48 hours. Queue time is separate.

Any failed group triggers workflow matrix fail-fast, including infrastructure
failures. This is deliberately stricter than stopping only on semantic errors.
An already-running partner may produce partial output before provider
cancellation takes effect. Retain completed/partial/cancelled/unstarted states.
No automatic retry, seed replacement or threshold adjustment is permitted.
Source changes cannot be pooled silently. A timeout is not a completed runtime.
